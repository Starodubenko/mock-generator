# mock-generator

Генератор синтетических документов и HTTP-моков. Один процесс NestJS обучает версионированный профиль схемы по эталонному корпусу, выпускает документы той же формы и отдаёт их соседнему микросервису. Операторский пульт рисуется в том же процессе (SSR, Material UI).

Тип документа — произвольный идентификатор, который заводит оператор. Сервис не привязан к конкретной предметной области: форма полей берётся из приложенных JSON.

## Возможности

- **Типы документов** — каталог профилей. Тип создают вручную, затем обучают и генерируют только его.
- **Обучение профиля** — эталон прикладывают файлами (`.json`, `.ndjson`, `.jsonl`). Сервис строит дерево путей, классы полей, связи и дифф с активной версией. Обучение само по себе рабочую версию не меняет.
- **Активация** — отдельный шаг. Смена типа или новое обучение не подменяет текущую версию контура, пока оператор её не активирует.
- **Генерация** — синтетические документы той же схемы. Идентификаторы выводятся из задания, ключа вариации и номера; значения корпуса в синтетику не копируются.
- **Публикация через соседний микросервис** — генератор сам в поисковый кластер не пишет. Сначала черновик и просмотр пачки, затем пробная заливка, обновление индекса и золотые запросы интерфейса. Провал пробы останавливает полную публикацию.
- **Контуры** — стенд и его часовой пояс. Пустой список разрешённых контуров ничего не публикует. Цель, похожая на прод, отклоняется до первой заливки.
- **HTTP-моки** — группы и ручки, которые можно привязать к заданию генерации и отдавать снаружи.
- **Два режима данных** — без `INDEXER_BASE_URL` всё живёт в памяти (`LocalDataModule`). С адресом соседнего микросервиса состояние и индекс идут через test-indexer.

Пульт показывает метаданные процесса (контур, тип, версии, статусы заданий, карантин). Тел эталонного корпуса, токена и адреса соседнего микросервиса в HTML нет.

REST: `/api/v1`. Схема: `/api/docs`.

## Команды

```bash
npm install
npm test
npm run test:e2e
npm run build
```

Поднять Postgres, OpenSearch и test-indexer (при отсутствии Docker скрипт предложит установить):

```bash
npm run infra:prepare
```

Генератор против соседнего микросервиса:

```bash
npm run start:dev:neighbor
```

То же явно:

```bash
INDEXER_BASE_URL=http://127.0.0.1:3100 npm run start:dev
```

Windows (cmd / PowerShell):

```bat
set INDEXER_BASE_URL=http://127.0.0.1:3100&& npm run start:dev
```

```powershell
$env:INDEXER_BASE_URL="http://127.0.0.1:3100"; npm run start:dev
```

Без соседнего микросервиса — только память:

```bash
npm run start:dev
```

Соседний микросервис отдельно:

```bash
npm run indexer:install
npm run indexer:start
npm run indexer:test
```

Пульт: http://127.0.0.1:3000

## Стенд после `infra:prepare`

| Сервис     | Адрес                                |
| ---------- | ------------------------------------ |
| Postgres   | `127.0.0.1:5434` (indexer / indexer) |
| OpenSearch | http://127.0.0.1:9200                |
| Соседний микросервис | http://127.0.0.1:3100        |
| Генератор  | http://127.0.0.1:3000                |

Переменные — в `.env.example`. Для локального контура в `start:dev` уже заданы `ALLOWED_CONTOURS=test-stand:Europe/Moscow` и `CONSOLE_SESSION_REQUIRED=false`.
